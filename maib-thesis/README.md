# کد پایان‌نامه: دسته‌بندی گزارش‌های حوادث دریایی MAIB

کد دقیقاً مطابق بخش «روش تحقیق» پروپوزال ([`../docs/proposal/Proposal.pdf`](../docs/proposal/Proposal.pdf)) است.

## ساختار: هر گام پروپوزال یک فایل

| فایل | گام پروپوزال | کار |
|---|---|---|

| `step2_tfidf_svm.py` | گام ۲-الف | خط مبنای کلاسیک TF-IDF + SVM، با و بدون oversampling |
| `models.py` | گام‌های ۲-ب، ۲-ج و ۳ | سه مدل: `bert`، `bert_bilstm` (مقاله‌ی مرجع)، `bert_bilstm_att` (روش پیشنهادی) |
| `losses.py` | گام ۴ | چهار تابع زیان: `ce`، `wce`، `focal`، `cb` |

| `step6_attention.py` | گام ۵ | تحلیل کیفی وزن‌های توجه |
| `step7_augment.py` | تکمیلی | افزایش داده با مدل زبانی: بازنویسی گزارش‌های کلاس‌های کمیاب |
| `common.py` | — | توابع کمکی: خواندن داده، محاسبه‌ی معیارها |

**ترتیب خواندن کد برای فهمیدن پروژه:** `config.py` ← `step1` ← `step2` ← `models.py` ← `losses.py` ← `step3` ← `step4` ← `step5` ← `step6`

## جدول آزمایش‌ها (`config.EXPERIMENTS`)

| مدل | زیان | گام | سؤال |
|---|---|---|---|
| `bert` | `ce` | ۲-ب | BERT با طبقه‌بند ساده |
| `bert_bilstm` | `ce` | ۲-ج | بازتولید مقاله‌ی مرجع |
| `bert_bilstm_att` | `ce` | ۳ | **RQ1:** آیا توجه کمک می‌کند؟ |
| `bert_bilstm_att` | `wce` | ۴-الف | **RQ2:** وزن معکوس فراوانی |
| `bert_bilstm_att` | `focal` | ۴-ب | **RQ2:** زیان کانونی |
| `bert_bilstm_att` | `cb` | ۴-ج | **RQ2:** تعداد مؤثر نمونه |

نتایج فعلی با ۲ seed (۱ و ۲) هستند: ۶ × ۲ = ۱۲ اجرا، به‌علاوه‌ی TF-IDF + SVM (گام ۲-الف). seed سوم گام بعدی است.

### آزمایش تکمیلی: oversampling (درخواست استاد راهنما)

به‌جای تغییر تابع زیان، کلاس‌های کمیاب **بیشتر دیده می‌شوند**:

| مدل | روش | فایل |
|---|---|---|
| TF-IDF + SVM | گزارش‌های کلاس‌های کوچک‌تر به‌صورت تصادفی کپی می‌شوند تا همه‌ی کلاس‌ها هم‌اندازه‌ی بزرگ‌ترین کلاس شوند | `step2_tfidf_svm.py` |
| `bert_bilstm_att + ce` | هر گزارش با احتمال «۱ تقسیم بر اندازه‌ی کلاسش» انتخاب می‌شود؛ طول epoch ثابت می‌ماند | `step3_train.py` (`--oversample`) |

فقط **داده‌ی آموزش** oversample می‌شود؛ val و test دست‌نخورده‌اند. oversampling با `ce` ترکیب شده و نه با `wce`، چون ترکیب هر دو نامتوازنی را دو بار جبران می‌کند.

### آزمایش‌های تکمیلی جلسه‌ی ۱۹ مهر ۱۴۰۵ (درخواست استاد راهنما)

**۱. افزایش داده (Data Augmentation) با مدل زبانی.** oversampling فقط گزارش‌ها را کپی می‌کرد و اطلاعات تازه‌ای نمی‌داد. حالا یک مدل زبانی کوچک (`Qwen/Qwen2.5-1.5B-Instruct`) گزارش‌های واقعی **آموزش** کلاس‌های کمیاب را با کلمه‌ها و ساختار جمله‌ی دیگر بازنویسی می‌کند (paraphrasing). واقعیت‌ها همان می‌مانند، پس برچسب هم همان است.

- هر کلاسی که کمتر از ۴۰۰ گزارش آموزش دارد تا ۴۰۰ پر می‌شود (`config.AUGMENT_TARGET`)، یعنی حدود ۱٬۰۷۰ گزارش جدید.
- فقط داده‌ی آموزش بازنویسی می‌شود. val و test صددرصد واقعی‌اند و هیچ‌وقت به مدل زبانی داده نمی‌شوند.
- بازنویسی‌های خیلی کوتاه یا بلند، تقریباً یکسان با اصل، بی‌ربط به اصل (مثلاً به زبان دیگر) و تکراری دور ریخته می‌شوند.
- **بررسی برچسب:** یک TF-IDF + SVM که فقط روی گزارش‌های **واقعی** آموزش دیده، هر بازنویسی را دسته‌بندی می‌کند. اگر بازنویسی دیگر در کلاس گزارش اصلی نیفتد (یعنی مدل زبانی واقعیتی را عوض کرده)، استفاده نمی‌شود و یک بازنویسی دیگر جایش ساخته می‌شود (مثل روش LAMBADA، Anaby-Tavor et al., 2020). درصد بازنویسی‌هایی که از این بررسی رد شده‌اند در `reports/augmentation_examples.md` می‌آید.
- اگر `step7_augment.py` را بعد از تمام شدن دوباره اجرا کنی، فقط برچسب‌ها را دوباره بررسی می‌کند، جای ردشده‌ها بازنویسی تازه می‌سازد و فایل‌ها را از نو می‌نویسد.
- `reports/augmentation_examples.md` چند نمونه‌ی اصل و بازنویسی را کنار هم نشان می‌دهد. **قبل از آموزش، آن را با چشم بررسی کن.**
- با `ce` و با `wce` آموزش داده می‌شود (`config.AUGMENT_EXPERIMENTS`) و با بدون اقدام، oversampling و wce مقایسه می‌شود.

**۲. BiLSTM بزرگ‌تر.** تعداد واحدها و لایه‌های BiLSTM در مدل پیشنهادی با `wce` (بهترین تابع زیان) تغییر می‌کند (`config.BILSTM_SIZES`):

| واحد در هر جهت | لایه | خروجی برای هر کلمه | توضیح |
|---:|---:|---:|---|
| 128 | 1 | 256 | پیش‌فرض (جدول اصلی) |
| 384 | 1 | 768 | هم‌اندازه‌ی خروجی BERT |
| 128 | 2 | 256 | دو لایه‌ی پشت‌سرهم |
| 384 | 2 | 768 | هر دو |

## اجرا

```bash
pip install -r requirements.txt
python step1_prepare_data.py                                # دادگان (چند ثانیه)
python step2_tfidf_svm.py                                   # SVM با و بدون oversampling (چند ثانیه)
python step4_run_experiments.py --seeds 1 2                 # ۱۲ اجرای BERT (حدود ۱۵ ساعت روی GTX 1650 Ti)
python step4_run_experiments.py --oversample --seeds 1 2    # ۲ اجرای oversampling (حدود ۲٫۵ ساعت)
python step5_report.py
python step6_attention.py

# آزمایش‌های تکمیلی (حدود ۱۵ ساعت GPU)
python step7_augment.py                                     # بازنویسی با مدل زبانی (بار اول ۳ گیگابایت دانلود)
python step2_tfidf_svm.py                                   # SVM روی داده‌ی افزوده (چند ثانیه)
python step4_run_experiments.py --augment --seeds 1 2       # ۴ اجرا، هر کدام حدود ۹۵ دقیقه
python step4_run_experiments.py --bilstm-sizes --seeds 1 2  # ۶ اجرا، هر کدام حدود ۸۰ دقیقه
python step5_report.py
```

- اگر اجرای `step4` قطع شد، همان دستور را دوباره بزن. اجراهایی که فایل نتیجه‌شان در `results/` هست رد می‌شوند.
- `step7_augment.py` هم اگر قطع شد، با اجرای دوباره از همان‌جا ادامه می‌دهد. اگر حافظه‌ی GPU کم آمد، در `config.py` مدل کوچک‌تر `Qwen/Qwen2.5-0.5B-Instruct` را بگذار.
- **`--seeds` را جا نینداز:** مقدار پیش‌فرض در `config.py` سه seed است و بدون آن، اجراهای seed سوم هم شروع می‌شوند.

## تصمیم‌های روش‌شناختی (برای فصل ۳)

1. **۹ کلاس به‌جای ۱۱:** دو کلاس `Hull Failure` (۳ گزارش) و `Non-accidental Event` (۲ گزارش) حذف شدند. با این تعداد، مجموعه‌ی آزمون فقط ۰ یا ۱ نمونه از آن‌ها داشت و یک پیش‌بینی به‌تنهایی Macro-F1 را چند واحد جابه‌جا می‌کرد. آستانه در `config.MIN_REPORTS_PER_CLASS` قابل تغییر است.
2. **یک تقسیم ثابت برای همه‌ی مدل‌ها** (`SPLIT_SEED = 42`). seed آموزش جدا از seed تقسیم است.
3. **انتخاب بهترین epoch فقط با validation.** مجموعه‌ی آزمون فقط یک بار، در پایان هر اجرا، استفاده می‌شود.
4. **وزن‌های کلاس فقط از داده‌ی آموزش** محاسبه می‌شوند.
5. **دستور آموزش یکسان برای همه‌ی مدل‌ها:** learning rate برابر 2e-5 برای BERT و 1e-3 برای لایه‌های جدید، batch مؤثر ۳۲ (مثل مقاله‌ی مرجع)، دقت مختلط و انباشت گرادیان. با این کار تفاوت نتایج فقط از معماری یا تابع زیان می‌آید.
   - مقاله‌ی مرجع learning rate را 1e-6 گزارش کرده است. این تنظیم برای همگرایی ده‌ها epoch لازم دارد. برای بازتولید دقیق آن، دستور اختیاری زیر را اجرا کن. نتیجه در جدول با برچسب `[paper_lr]` می‌آید:
     ```bash
     python step4_run_experiments.py --paper-settings --seeds 1 2
     ```
6. **معیار اصلی:** Macro-F1 و recall هر کلاس، به‌ویژه سه کلاس ایمنی‌بحرانی (`config.CRITICAL_CLASSES`). Accuracy فقط برای مقایسه با ادبیات گزارش می‌شود.
7. **میانگین ± انحراف معیار روی seedها.** `step5_report.py` هر تفاوت را با انحراف معیار seedها مقایسه می‌کند و می‌گوید تفاوت بزرگ‌تر از نوسان تصادفی است یا نه. این آزمون معناداری آماری نیست.
